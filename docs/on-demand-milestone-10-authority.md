# Milestone 10: bounded authority resolution

Fresh stress runs and transition-package preflights now freeze a separate plan for at most 20 positive-balance non-wallet token accounts before attempting control resolution. The selector first covers distinct coarse-classification/runtime-owner hints, taking the highest raw balance in each, then fills the budget by descending balance and token-account address. It never replaces a selected case after an unsuccessful result. The plan pins the population capture digest, exact token accounts, recorded authorities, raw balances, selection reasons, selector version and fixed server budget. The browser supplies none of these inputs.

The existing population acquisition already retrieves the recorded authority account of every positive-balance token account under its own bound. The new resolver reuses those captured bytes and RPC pointers; it performs **zero additional RPC requests** and fetches zero linked accounts. Its fixed ceiling reserves 8 linked accounts and 3 adapters per case for future trusted adapters, but neither capability is exercised here. The saved authority report records account existence, curve status, runtime owner, executable flag, byte length and SHA-256, lamports, control path and the population evidence pointer. Original token and authority bytes remain in the capture. Offline replay re-decodes the population, reselects the frozen plan and reconstructs each result; a serialized resolution claim alone is rejected.

The narrow supported control adapter verifies a Meteora DLMM `LbPair` layout, exact pool PDA and bump, canonical source vault PDA, source mint and selected token-account address. This proves protocol custody for that exact account. It does **not** prove that a holder owns a position, that withdrawal is possible, or that the pool can sign the candidate conversion. A decoded SPL Token multisig provides its exact threshold and members, but private approvals are unavailable, so conversion is Unsupported. The retained SPACEX and second-asset selections contain no SPL Token multisig or Squads case. Existing Phase 9 Squads derivation is investigation code, not a reusable transaction/approval adapter; arbitrary PDA seed search is never attempted. Every other program-owned authority is partial, and an absent or otherwise unknown authority stays unresolved. Off-curve alone never yields PDA proof.

The authority report has a separate conversion status. None of the selected non-wallet accounts receives a locally assumed signer, executable-candidate eligibility or Proven conversion. A verified DLMM pool vault cannot be converted through the current candidate instruction: a legitimate sequential path would require a separately captured position and real protocol withdrawal, followed by conversion in **one evolving VM bank**. The current conversion and position executors create independent banks, so their outputs cannot be composed into a sequential proof. No such path was attempted. The 5-case executable-program budget, 120-second VM timeout, serial execution, 2 MiB RPC response and 4 MiB artifact ceilings are persisted; no program execution or linked RPC capture was used by this resolver.

The preflight report includes exact counts and raw public balances for initial classes, selected outcomes and the unselected remainder. Its refined stress-world digest binds population, authority plan and stress plan. The existing ConversionStressReadiness and PopulationRolloutReadiness policies remain separate and unchanged. With no newly executable control path, the stress selector still chooses the same direct-wallet candidates; successful custody resolution cannot make either readiness status Ready. The Milestone 9 block-only/strict gate retains its policy mapping and now includes authority coverage as an explanatory reason. Historical Milestone 8/9 reports replay without authority artifacts and retain their original bytes.

For the browser stress flow, `plan-authority-resolution` and `resolve-authority-resolution` run after the fresh population capture and before the stress plan. The offline stress replay recomputes the authority report and emits the joint world digest. Consumer mode shows bounded control coverage; technical mode includes exact accounts, controllers and evidence. A refresh creates a different population digest and rejects the old plan. No private keys, multisig signatures, network transaction or wallet signer are introduced.

Sixteen cases were partial and three unresolved; 3,012 non-wallet positive-balance accounts remained outside the selection. An offline package worker and replay using the tracked SPACEX capture reproduced the new report and block-only WARN without changing analytical readiness. Historical Milestone 9 package replay also passed unchanged.
