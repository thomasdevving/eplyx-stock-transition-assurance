# Milestone 12: operator rollout invariants

Package schema 2 adds `invariantSchemaVersion: 1` and 1–16 typed `invariants` to `eplyx.json`. Each definition requires `type` and `severity` (`blocking` or `warning`). `required_path_available` also requires `path`, restricted to `ReplacementConversion` or `OfficialTransition`. Unknown types, fields, severities, paths and duplicate type/config pairs are rejected before RPC. Definitions are sorted for package identity; array order has no meaning. Type, severity and path changes alter `transition_package_sha256`, so prior captures cannot be reused under changed requirements. Schema 1 packages and saved reports retain their original identities and replay bytes.

| Type | Exact scope | Satisfied | Violated | Indeterminate |
| --- | --- | --- | --- | --- |
| `conversion_output_matches` | One candidate conversion, amount, program, proposed reserve and captured execution bank | VM status Proven and the existing reconciliation is true | The exact candidate VM conversion executed and Failed | No reconciled successful execution |
| `no_selected_case_failed` | Frozen selected stress cases | Every selected case has a matching Proven result | At least one selected case Failed | Empty selection, unmatched result or any unknown outcome without a failure |
| `required_path_available` | Exact `ReplacementConversion` or separate `OfficialTransition` | That exact path is Proven | That exact path Failed in execution | NotTested, Unsupported or Indeterminate |
| `authority_model_supported` | Frozen selected non-wallet authority cases | Every selected case has proven supported candidate execution | A resolved selected case explicitly has an Unsupported conversion path | No cases, partial or unresolved control, or missing execution proof |
| `no_positive_balance_stranded` | Observed positive-balance population | Not presently attainable: exhaustive account-bound path evidence is absent | Not presently inferable from bounded samples | Any nonempty or incomplete population |

`no_positive_balance_stranded` is NotApplicable only when complete enumeration proves zero positive-balance accounts. It cannot become Satisfied from selected wallet or authority samples. The current result model records invariant ID, type, config, severity, scope, four-state status, exact capture digests, explanation and evaluator version. It reads verified results after conversion, stress, authority resolution and analytical readiness are finalized. Invariants never select cases, execute a transaction, introduce proof, grant issuer authorization or change CandidatePlanReadiness, ConversionStressReadiness, PopulationRolloutReadiness or OfficialTransition.

The deployment gate incorporates findings separately from analytical readiness. A blocking Violated finding blocks under both policies. Blocking Indeterminate warns under block-only and blocks under strict. Warning Violated or Indeterminate warns under either policy. Satisfied and NotApplicable have no gate effect. Existing analytical Blocked/Incomplete policy remains in force. The report's `Rollout invariants` section is included automatically in the example GitHub Actions Job Summary. Offline replay re-executes the existing VM checks, reconstructs authority findings, re-evaluates invariants and gate, and compares saved JSON and Markdown bytes. Saved invariant fields are never evidence.

The operator templates are `examples/transitions/demo-invariants-healthy`, `demo-invariants-underfunded` and `demo-invariants-second`. Assemble each with `node scripts/assemble-transition-package.mjs <template> <candidate.so> <new-output-directory>`, then run `eplyx-lifecycle preflight <package> --gate block-only --out <result-directory>`. The package may contain only the registered candidate program and bounded typed terms; invariant definitions provide no scripts, field paths, account reads, RPC URL or claimed status. The read-only RPC credential remains in the local environment. Neither the candidate program nor the reserve is deployed or issuer-verified.

FastRPC acceptance on 2026-09-23 completed population enumeration and coherent local candidate conversion for the healthy SPACEX package and second asset. Their output invariant was Satisfied, but the provider rejected the recorded-authority batch, so no live stress case was selected. Authority, selected-case and population requirements were Indeterminate. Block-only returned WARN; strict offline reevaluation returned BLOCK. The underfunded package executed locally and Failed, making `conversion_output_matches` Violated and the block-only gate BLOCK. Its stress cases also remained unavailable due to the same authority batch limit; no stress failure is claimed. All three saved packages replayed offline. Exact hashes and validation commands are in `reports/milestone12-validation.json`.

A later FastRPC retry on the same date succeeded with the previously rejected 100-address `getMultipleAccounts` batch. Fresh schema 2 preflights for SPACEX (healthy and underfunded) and the second asset each completed token-account enumeration and recorded-authority inspection, selected 20 non-wallet authority cases and froze 10 wallet stress cases. Every selected stress result was Indeterminate because its source account differed from the frozen population evidence at final recapture; no peer was substituted and no stress conversion was Proven. The healthy candidate conversion was Proven locally; the second candidate was Indeterminate after source drift; the underfunded candidate Failed in the local VM. The authority-model invariant was Violated in all three runs because a resolved protocol-internal account has an Unsupported candidate conversion path. Both healthy and second runs retained block-only WARN, while underfunded remained BLOCK. OfficialTransition stayed NotTested, and both rollout readiness scopes remained Incomplete. Offline replay reproduced all three saved results, including the underfunded analytical exit code 3. These new captures are separate from the earlier provider refusal; exact outcomes and hashes are in [`reports/milestone12-fastrpc-retry.json`](../reports/milestone12-fastrpc-retry.json).

The supplied `aperture-txstream.rpcfast.com:443` address is [FastRPC Aperture TxStream](https://rpcfast.com/blog/aperture-txstream-real-time-simulation), an early transaction stream. The completed authority retry used finalized JSON-RPC account responses. [FastRPC Yellowstone gRPC](https://docs.rpcfast.com/rpc-fast-api/yellowstone-grpc) is a separate streaming service and was not used to establish these account snapshots. No mainnet transaction was sent.

Reserve sufficiency across selected cases, source residual and mint-supply change invariants are deferred until their adapter contracts and complete exact scopes are independently specified. They cannot be approximated from a successful candidate status or a bounded sample.
