# Milestone 14: bounded counterexample search

`search-counterexamples <package> --result <verified-preflight-directory> --out <new-directory>` replays the pinned package report, then searches its exact coherent Milestone 13 stress cases. Add `--live-observed` to inspect up to 25 further exact accounts from the same captured population. This option requires the server-controlled `SOLANA_RPC_URL` and makes bounded finalized read-only requests. Each additional wave writes and syncs `wave-N.plan.json` before capture; a failed, drifted or unavailable case stays selected. The next wave is selected from earlier wave results only. No transaction is broadcast.

The observed selector checks executable authority and state shape, then ranks untested accounts by a new executable shape, distance to an earlier exact failure's balance, descending balance and account address. It freezes the account, reason, FullAtFinalCapture amount policy, package digest and selector version in `wave-N.freeze.json` before capture. Final coherent state and the candidate program are rechecked by the existing stress executor. Wave captures, plans and freeze manifests are retained next to `counterexamples.json`. Offline `replay-counterexample <package> --result <parent> --search <search-directory>` reconstructs wave choices, executes the captured cases and derived probes again, and compares the canonical artifact byte for byte. It makes no RPC request.

Observed counterexamples require an actual failed candidate instruction and watched-state rollback against a coherent final captured account. Derived counterexamples retain the observed account, final capture digest and original amount, plus the changed value and distinct provenance. Source-amount variants are limited to `max(1, captured withheld transfer fees)..observed final raw balance - 1`; decoded token account amount and captured source mint supply are rebuilt together through Token-2022 state packing. The remaining account fields are retained. No source mutation is available when the captured amount equals that lower bound. Reserve variants are limited to the operator's proposed funding through the exact expected gross release and are built with the registered proposed-account constructor. Source and mint bytes are marked `DerivedForSearch`; a modified proposed reserve is marked `DerivedProposedForSearch`. These variants are never described as current chain state.

The registered fixed-ratio adapter makes the expected release nondecreasing in raw input for a validated plan. Integer binary search locates the first amount whose expected release exceeds the proposed reserve, and actual LiteSVM executions check that amount and its immediate predecessor. A separate pair of local executions checks reserve `required-1` and `required`. The pure model locates candidates; only executed, reconciled results create findings. A minimality claim requires the adjacent passing amount and the same failure signature as the original, when one exists. The signature records execution stage, program, instruction error, relevant failure log and verified watched rollback. If monotonicity is unavailable, the bounded model search uses ordered probing. Fee, ratio, authority, delegate and arbitrary account or instruction mutation are outside this version.

The server budget is 25 additional observed selections, 20 boundary VM probes and 20 minimization VM probes. Execution is serial; a derived VM probe has a fixed 120-second wall-clock deadline, after which the entire search fails without a finding. The saved derived domain records exact source and reserve bounds; a derived reserve cannot exceed the captured replacement mint supply when reserve search is active. Wave captures use the existing per-case finalized RPC timeout and existing artifact bounds; the summary artifact is capped at 16 MiB. The browser cannot supply a budget, endpoint, mutation function, account bytes, program ID, instruction or claimed outcome. The candidate SBF bytes come only from the validated package.

`gate-counterexamples <package> --result <parent> --search <search-directory> --gate block-only|strict` first replays the search. A found exact observed failure or valid derived failure adds a separate blocking `CounterexampleFinding` to the deployment decision. Original analytical readiness, invariant results, population coverage and `OfficialTransition = NotTested` remain unchanged. With no finding, the output says **“No counterexample found within this search domain and budget.”** It makes no absence claim. The parent package report and all historical schema replay bytes remain untouched.
