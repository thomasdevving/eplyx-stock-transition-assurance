# Milestone 5 reuse audit

- Generic `AssetLifecyclePolicy::status_at`, provenance validation and `classify_public_exposure` already implement the desired time-dependent interpretation. Add one neutral post-deadline status, and reuse that classification for the decoded current account. Do not fabricate a Phase 2 population snapshot.
- Historical counterfactual `ProductionWorld`, resolution `phase7`, readiness `evidence` and notice compatibility bridge bind frozen files and must remain historical adapters. Current analysis will not call them.
- Current wallet v3 `evaluate` reconstructs exact mint/owner/account state from saved RPC bytes. Bind the enclosing server run ID and capture digest plus selected account and raw account digest in a new scenario.
- `probe::current::VerifiedExecution` can only be reconstructed through VM replay. Adapt that typed output into the existing path resolver's attempts, requiring exact run/wallet/source/mint/owner identity.
- Reuse existing `PathCondition`, `EvidenceScope`, requirement evaluator and status aggregation. Provide entity-only presets with no population requirement/output. The minimum mobility scope is one exact selected tested amount/recipient/route; it never implies full-balance coverage.
- Keep current checks' fixtures/banks independent from the wallet observation. Proposed times change relevance, not proof. A future effective time is checked at scenario creation; saved offline replay never consults wall-clock time.
- Current scenarios are UserProposed. Successor inspection is independently acquired with existing mint pipeline, no sampling; mint existence cannot prove issuer relationship, ratio or conversion.
